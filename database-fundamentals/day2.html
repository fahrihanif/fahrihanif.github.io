Bab 18 / 82

Autogrowth

Saat file penuh, SQL Server memperbesarnya otomatis. Setiap pembesaran membuat query menunggu.

  • Pertumbuhan terlalu kecil dan terlalu sering memperlambat aplikasi
  • Pertumbuhan dalam persen berbahaya: file 100 GB tumbuh 10% menambah 10 GB sekaligus
  • Di produksi: ukuran awal cukup besar, pertumbuhan dalam MB yang tetap

Perhatian

Log file membengkak sampai memenuhi disk? Penyebab paling umum: recovery model FULL tanpa backup log rutin (Hari 5).

MONEY vs DECIMAL

DECLARE @m1 MONEY = 1, @m2 MONEY = 3;
DECLARE @d1 DECIMAL(19,4) = 1, @d2 DECIMAL(19,4) = 3;

SELECT @m1 / @m2 AS HasilMoney,     -- 0.3333

Bab 220 / 82

Prefix N: '...' vs N'...'

Definisi

Tanpa N ('Budi') dibaca sebagai VARCHAR, mengikuti code page collation.

Dengan N (N'Budi') dibaca sebagai NVARCHAR (Unicode). N dari National.

SQL Server mengonversi literal ke tipenya lebih dulu, baru memasukkannya ke kolom. Karakter yang hilang, hilang sebelum sampai ke kolom.

Dampak collation

  • Pencarian: WHERE Name = 'budi' juga menemukan "Budi" dan "BUDI"

Bab 229 / 82

Binary dan data type khusus

Data besar

  • VARBINARY(MAX), NVARCHAR(MAX) hingga 2 GB
  • Menyimpan file: isi di database vs path saja; umumnya path lebih dipilih
  • TEXT, NTEXT, IMAGE sudah deprecated

Khusus

  • UNIQUEIDENTIFIER: GUID 16 byte; NEWID() acak menyebabkan fragmentation jika dijadikan clustered PK
  • ROWVERSION: berubah otomatis setiap baris diubah, dasar optimistic concurrency
  • SQL_VARIANT: hindari
Bab 230 / 82

Konversi data type

SELECT CAST('123' AS INT)              AS A,   -- 123
       TRY_CAST('12a' AS INT)          AS B,   -- NULL, bukan error
       CONVERT(VARCHAR(10), GETDATE(), 103) AS C;   -- dd/mm/yyyy

Precedence (sebagian, dari tertinggi): tanggal → FLOAT → DECIMAL → INT → BIT → NVARCHAR → VARCHAR

Perhatian

WHERE KodePos = 12345 pada kolom VARCHAR: kolom dikonversi ke INT di setiap baris. Query bisa gagal (Msg 245) dan index tidak terpakai optimal. Bandingkan dengan literal teks.

Menulis constraint

CREATE TABLE dbo.Employee (
    EmployeeID   INT IDENTITY(1,1) CONSTRAINT PK_Employee PRIMARY KEY,
    DepartmentID INT           NOT NULL,

Bab 338 / 82

PRIMARY KEY dan IDENTITY

  • Primary key otomatis membuat index unik, secara default clustered
  • PK gabungan ditulis table-level: CONSTRAINT PK_OrderDetail PRIMARY KEY (OrderID, ProductID)
  • IDENTITY(1,1): mulai 1, bertambah 1

Perhatian

Nilai IDENTITY bisa melompat: INSERT yang gagal atau di-rollback tetap memakai nomornya, dan restart server bisa melompatkan nilai. Tidak cocok untuk nomor faktur pajak yang wajib berurutan tanpa celah.

Bab 340 / 82

FOREIGN KEY

CONSTRAINT FK_Employee_Department
    FOREIGN KEY (DepartmentID) REFERENCES dbo.Department (DepartmentID)
    ON DELETE NO ACTION     -- default
    ON UPDATE NO ACTION

Tips dari lapangan

SQL Server tidak otomatis membuat index untuk kolom foreign key, padahal kolom ini sering dipakai JOIN dan pemeriksaan saat data induk dihapus (Hari 5).

Filtered unique index

ALTER TABLE dbo.Employee DROP CONSTRAINT UQ_Employee_Email;

CREATE UNIQUE NONCLUSTERED INDEX UQ_Employee_Email
    ON dbo.Employee (Email)
    WHERE Email IS NOT NULL;

  • Butuh ANSI_NULLS dan QUOTED_IDENTIFIER ON (default di SSMS)
  • Bukan constraint, jadi tidak bisa dirujuk foreign key

UPDATE dan DELETE yang aman

Tiga kebiasaan

  1. Jalankan SELECT dengan WHERE yang sama lebih dulu
  2. Ubah SELECT menjadi UPDATE/DELETE tanpa mengubah WHERE
  3. Periksa jumlah baris yang berubah (@@ROWCOUNT)

Perhatian

Tanpa WHERE, seluruh isi tabel berubah. Sering terjadi saat hanya sebagian script diblok lalu ditekan F5.

Melihat perubahan

UPDATE dbo.Employee
SET    Salary = Salary * 1.10
OUTPUT deleted.Salary AS GajiLama,
       inserted.Salary AS GajiBaru
WHERE  DepartmentID = 1;

SELECT FirstName + ' ' + MiddleName + ' ' + LastName   AS PakaiPlus,      -- NULL jika MiddleName NULL
       CONCAT(FirstName, ' ', MiddleName, ' ', LastName) AS PakaiConcat,   -- NULL = teks kosong
       CONCAT_WS(' ', FirstName, MiddleName, LastName)   AS PakaiConcatWs  -- lewati NULL

WHERE dan prioritas AND/OR

-- Dibaca: Color = 'Black' OR (Color = 'Red' AND ListPrice > 1000)
WHERE Color = 'Black' OR Color = 'Red' AND ListPrice > 1000

BETWEEN dan filter tanggal

BETWEEN a AND b bersifat inklusif, sama dengan >= a AND <= b.

-- Semua order bulan Juni 2008, apa pun jamnya
SELECT SalesOrderID, OrderDate
FROM   SalesLT.SalesOrderHeader
WHERE  OrderDate >= '20080601' AND OrderDate < '20080701';

Untuk kolom tanggal-jam, pola >= dan < lebih aman daripada BETWEEN.

ORDER BY, TOP, dan paging

SELECT TOP (5) Name, ListPrice FROM SalesLT.Product ORDER BY ListPrice DESC;

DECLARE @Page INT = 3, @PageSize INT = 20;
SELECT ProductID, Name, ListPrice
FROM   SalesLT.Product
ORDER BY ListPrice DESC, ProductID          -- penentu urutan yang unik
OFFSET (@Page - 1) * @PageSize ROWS FETCH NEXT @PageSize ROWS ONLY;
  • NULL berada paling atas pada urutan ASC
  • TOP tanpa ORDER BY tidak menjamin baris mana yang diambil
  • Paging butuh urutan unik, jika tidak baris bisa muncul dua kali atau terlewat
