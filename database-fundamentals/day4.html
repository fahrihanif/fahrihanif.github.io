Batch dan GO

  • Variabel hanya hidup di dalam satu batch: setelah GO, variabel sebelumnya sudah tidak dikenal
  • CREATE VIEW, CREATE PROCEDURE, CREATE FUNCTION, CREATE TRIGGER, dan CREATE SCHEMA wajib menjadi perintah pertama dalam batch-nya
  • Karena itu kamu akan sering melihat GO sebelum dan sesudah pembuatan objek
CREATE OR ALTER VIEW dbo.vw_Contoh
AS
SELECT 1 AS Angka;
GO

SELECT * FROM dbo.vw_Contoh;

Bab 212 / 63

Membuat dan memakai view

Definisi

View adalah query yang disimpan di database dan diberi nama. Yang tersimpan hanya definisinya; datanya tetap diambil dari tabel asli setiap kali dipanggil.

CREATE OR ALTER VIEW dbo.vw_ProductCatalog
AS
SELECT p.ProductID, p.Name AS ProductName, c.Name AS CategoryName, p.ListPrice
FROM   SalesLT.Product         AS p
JOIN   SalesLT.ProductCategory AS c ON c.ProductCategoryID = p.ProductCategoryID;
GO

SELECT * FROM dbo.vw_ProductCatalog WHERE CategoryName = N'Road Bikes';
Bab 213 / 63

Kapan view dipakai

  • Menyederhanakan query berulang: JOIN yang sama dipakai banyak laporan cukup ditulis sekali
  • Membatasi kolom demi keamanan: pengguna diberi akses ke view, bukan ke tabel aslinya
  • Memberi nama pada logika bisnis: "ringkasan order" menjadi istilah bersama tim
  • Menjaga kompatibilitas: struktur tabel berubah, definisi view disesuaikan, aplikasi lama tetap jalan
Bab 214 / 63

Keterbatasan view

  • Tidak menerima parameter. Butuh parameter? Pakai inline table-valued function (Bab 3)
  • ORDER BY tidak boleh di dalam view (kecuali bersama TOP/OFFSET, dan urutannya tetap tidak dijamin). Urutkan di query pemanggil
  • Bukan penyimpanan data. View tidak mempercepat query dengan sendirinya

Perhatian

Hindari view di atas view di atas view. Setiap lapisan menyembunyikan JOIN dan filter tambahan, sehingga query yang tampak sederhana ternyata menyentuh belasan tabel.

Kenapa scalar function bisa memperlambat query

Scalar function di SELECT atau WHERE dijalankan untuk setiap baris. Pada tabel jutaan baris, satu function sederhana bisa membuat query berkali-kali lebih lambat.

Parameter input, default, dan OUTPUT

CREATE OR ALTER PROCEDURE dbo.usp_CariProduk
    @Keyword     NVARCHAR(50),
    @MaksHarga   DECIMAL(12,2) = NULL,   -- opsional
    @JumlahHasil INT OUTPUT
AS
BEGIN
    SET NOCOUNT ON;
    SELECT ProductID, Name, ListPrice
    FROM   SalesLT.Product
    WHERE  Name LIKE N'%' + @Keyword + N'%'
      AND  (@MaksHarga IS NULL OR ListPrice <= @MaksHarga);
    SET @JumlahHasil = @@ROWCOUNT;
END;

Perhatian

Bab 638 / 63

XACT_ABORT dan XACT_STATE

  • Secara default, sebagian error tidak membatalkan transaksi: perintah berikutnya tetap berjalan (kamu melihatnya di L2.6)
  • SET XACT_ABORT ON: hampir semua error langsung membatalkan seluruh transaksi. Praktik baku untuk procedure yang mengubah data
  • XACT_STATE(): 1 masih bisa di-commit, -1 harus di-rollback, 0 tidak ada transaksi

Pola baku procedure dengan transaksi

CREATE OR ALTER PROCEDURE dbo.usp_Contoh @Param INT
AS
BEGIN
    SET NOCOUNT ON;
    SET XACT_ABORT ON;
    BEGIN TRY
        BEGIN TRAN;
            -- perubahan data
            -- validasi; jika dilanggar: THROW 50010, N'...', 1;
        COMMIT;
    END TRY
    BEGIN CATCH
        IF @@TRANCOUNT > 0 ROLLBACK;
        THROW;                    -- teruskan error asli
    END CATCH
END;

Pengertian trigger

Definisi

Trigger adalah kode yang dijalankan otomatis saat terjadi INSERT, UPDATE, atau DELETE pada sebuah tabel. Tidak ada yang memanggilnya secara eksplisit.

Bab 749 / 63

Trigger wajib menangani banyak baris

-- SALAH: hanya satu baris
DECLARE @ProductID INT;
SELECT @ProductID = ProductID FROM inserted;   -- baris terakhir saja

-- BENAR: perlakukan sebagai kumpulan baris
INSERT INTO dbo.ProductListPriceAudit (ProductID, OldPrice, NewPrice)
SELECT d.ProductID, d.ListPrice, i.ListPrice
FROM   deleted  AS d
JOIN   inserted AS i ON i.ProductID = d.ProductID
WHERE  d.ListPrice <> i.ListPrice;

Perhatian

Trigger berjalan sekali per perintah, bukan per baris. Satu UPDATE yang mengubah 100 baris membuat inserted dan deleted berisi 100 baris.

Bab 750 / 63

Contoh: audit perubahan harga

CREATE OR ALTER TRIGGER SalesLT.trg_Product_ListPriceAudit
ON SalesLT.Product
AFTER UPDATE
AS
BEGIN
    SET NOCOUNT ON;
    IF NOT UPDATE(ListPrice) RETURN;    -- keluar jika harga tidak diubah

    INSERT INTO dbo.ProductListPriceAudit (ProductID, OldPrice, NewPrice)
    SELECT d.ProductID, d.ListPrice, i.ListPrice
    FROM   deleted  AS d
    JOIN   inserted AS i ON i.ProductID = d.ProductID

END;
Bab 751 / 63

Trigger berjalan di dalam transaksi yang sama

  • Jika transaksi di-rollback, baris audit yang ditulis trigger ikut dibatalkan
  • ROLLBACK di dalam trigger membatalkan seluruh perintah pemicunya
  • Trigger yang berat membuat setiap INSERT dan UPDATE melambat, dan transaksi lebih lama terbuka

Tips dari lapangan

Butuh catatan audit yang tetap ada walaupun transaksi dibatalkan? Trigger bukan alatnya; gunakan proses terpisah di luar transaksi.
