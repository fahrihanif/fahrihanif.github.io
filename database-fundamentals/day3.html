Kenapa perlu JOIN

Definisi

JOIN menggabungkan baris dari dua tabel berdasarkan kondisi di klausa ON, biasanya kecocokan foreign key dengan primary key.

Normalisasi memecah data agar setiap fakta tersimpan sekali. JOIN menyatukannya kembali saat query dijalankan, bukan saat disimpan.

Bab 17 / 58

CROSS JOIN dan cartesian product

-- 6 produk × 3 kategori = 18 baris
SELECT p.Name, c.Name AS Category
FROM   SalesLT.Product AS p
CROSS JOIN SalesLT.ProductCategory AS c;

Perhatian

Hasil jauh lebih banyak dari yang diharapkan? Periksa apakah ada tabel yang lupa diberi kondisi ON. Gejalanya: jumlah baris berlipat dan angka laporan membengkak.

Bab 18 / 58

INNER JOIN

SELECT h.SalesOrderID, h.OrderDate, c.FirstName, c.LastName
FROM   SalesLT.SalesOrderHeader AS h
JOIN   SalesLT.Customer         AS c ON c.CustomerID = h.CustomerID;

  • Hanya baris yang cocok di kedua tabel yang muncul
  • Hindari gaya lama FROM A, B WHERE A.id = B.id: satu kondisi terlupa langsung menjadi cartesian product

Bab 111 / 58

Mencari data tanpa pasangan

SELECT c.CustomerID, c.FirstName, c.LastName
FROM   SalesLT.Customer            AS c
LEFT JOIN SalesLT.SalesOrderHeader AS h ON h.CustomerID = c.CustomerID
WHERE  h.SalesOrderID IS NULL;

Pola LEFT JOIN ... IS NULL adalah cara baku mencari pelanggan tanpa order, produk yang belum pernah terjual, atau data master yang belum dipakai.

Bab 112 / 58

Jebakan: filter tabel kanan di WHERE

-- SALAH: LEFT JOIN berubah menjadi INNER JOIN
LEFT JOIN SalesLT.SalesOrderHeader AS h ON h.CustomerID = c.CustomerID
WHERE  h.OrderDate >= '20080101'

-- BENAR: kondisi tabel kanan ditulis di ON
LEFT JOIN SalesLT.SalesOrderHeader AS h
       ON h.CustomerID = c.CustomerID AND h.OrderDate >= '20080101'

Pelanggan tanpa order punya OrderDate NULL; perbandingan NULL bernilai UNKNOWN sehingga barisnya tersaring keluar.

Bab 113 / 58

SELECT h.SalesOrderID, c.CompanyName, p.Name AS ProductName, d.OrderQty

JOIN   SalesLT.SalesOrderDetail AS d ON d.SalesOrderID = h.SalesOrderID

Tips dari lapangan

Bangun bertahap: mulai dua tabel, jalankan, periksa jumlah baris, baru tambah tabel berikutnya.

Bab 115 / 58

Jebakan fan-out: angka terhitung ganda

-- SALAH: TotalDue terulang untuk setiap item order
SELECT SUM(h.TotalDue)
FROM   SalesLT.SalesOrderHeader AS h
JOIN   SalesLT.SalesOrderDetail AS d ON d.SalesOrderID = h.SalesOrderID;

-- BENAR: jumlahkan dari tabel header saja

-- BENAR: atau hitung ulang dari detail
SELECT SUM(d.OrderQty * d.UnitPrice) FROM SalesLT.SalesOrderDetail AS d;

Bab 116 / 58

Alias dan gaya penulisan

  • Beri alias singkat yang bermakna (c, od), lalu selalu tulis alias di depan nama kolom
  • Tanpa alias, kolom bernama sama di dua tabel menghasilkan error Ambiguous column name
  • Satu JOIN per baris, klausa ON disejajarkan
  • Sebutkan kolom yang dibutuhkan saja; SELECT * pada query multi-tabel menghasilkan banyak kolom duplikat

Jebakan: fungsi pada kolom di WHERE

-- Kurang efisien: index tidak bisa dipakai optimal
WHERE YEAR(OrderDate) = 2008

HAVING vs WHERE

WHEREHAVING
DiprosesSebelum pengelompokanSetelah pengelompokan

Bab 332 / 58

Agregasi setelah JOIN

SELECT c.CompanyName,
       COUNT(DISTINCT h.SalesOrderID) AS JumlahOrder,   -- DISTINCT karena baris terulang
       SUM(d.OrderQty * d.UnitPrice)  AS TotalBelanja
FROM   SalesLT.Customer         AS c
JOIN   SalesLT.SalesOrderHeader AS h ON h.CustomerID   = c.CustomerID
JOIN   SalesLT.SalesOrderDetail AS d ON d.SalesOrderID = h.SalesOrderID
GROUP BY c.CompanyName;

Perhatian

Pada LEFT JOIN, COUNT(*) tetap menghitung 1 untuk baris tanpa pasangan. Pakai COUNT(kolom tabel kanan) agar hasilnya 0.

Bab 333 / 58

Satu query menghasilkan beberapa kategori sekaligus, tanpa perlu menjalankan query terpisah.

DISTINCT, GROUP BY, dan ROLLUP

DISTINCT vs GROUP BY

Untuk sekadar menghilangkan duplikat, hasilnya sama. Pilih GROUP BY jika butuh nilai agregat.

Bab 441 / 58

Konsep OVER()

Definisi

Window function menghitung nilai atas sekumpulan baris tanpa menghilangkan baris detailnya. GROUP BY meringkas banyak baris menjadi satu; window function menambah kolom pada setiap baris.

SELECT Name, ListPrice,
       COUNT(*) OVER () AS TotalBaris
FROM   SalesLT.Product
WHERE  Color = 'Black';

OVER () yang kosong berarti window-nya seluruh hasil query.

Bab 442 / 58

ROW_NUMBER dan PARTITION BY

SELECT ROW_NUMBER() OVER (
           ORDER BY ListPrice DESC) AS No,
       Name, ListPrice
FROM   SalesLT.Product
ORDER BY ListPrice DESC;
SELECT h.CustomerID,
       h.SalesOrderID,
       ROW_NUMBER() OVER (
           PARTITION BY h.CustomerID
           ORDER BY h.OrderDate) AS OrderKe
FROM   SalesLT.SalesOrderHeader AS h;
  • ORDER BY di dalam OVER wajib ada
  • PARTITION BY memulai penomoran ulang di setiap kelompok
  • Nomornya dihitung setiap kali query dijalankan, jadi bukan identitas baris
Bab 443 / 58

Pagination lengkap dalam satu query

DECLARE @Page INT = 2, @PageSize INT = 10;

SELECT ROW_NUMBER() OVER (ORDER BY p.ListPrice DESC,
                                   p.ProductID) AS No,
       p.ProductID, p.Name, p.ListPrice,
       COUNT(*) OVER () AS TotalBaris
FROM   SalesLT.Product AS p
WHERE  p.Color = 'Black'
ORDER BY p.ListPrice DESC, p.ProductID
OFFSET (@Page - 1) * @PageSize ROWS
FETCH NEXT @PageSize ROWS ONLY;

COUNT(*) OVER () dihitung sebelum OFFSET ... FETCH, jadi nilainya jumlah seluruh baris hasil filter. Aplikasi tidak perlu query kedua untuk menghitung jumlah halaman.

Bab 444 / 58

Urutan yang pasti dan batas OFFSET

Perhatian

Pagination wajib memakai ORDER BY yang unik. Jika banyak baris punya nilai pengurut sama, satu baris bisa muncul di dua halaman atau terlewat. Tambahkan primary key sebagai penentu terakhir.

  • OFFSET besar tetap harus melewati baris sebelumnya, jadi halaman terakhir lebih lambat daripada halaman pertama
  • Untuk data sangat besar, pertimbangkan keyset pagination: menyaring berdasarkan nilai terakhir yang sudah ditampilkan
  • Dampak index terhadap query seperti ini dibahas di Hari 5

Sebelum OFFSET ... FETCH ada, pagination dilakukan dengan ROW_NUMBER bertingkat. Sekarang cukup: ROW_NUMBER untuk menampilkan nomor, OFFSET ... FETCH untuk memotong halaman.

OperatorHasil

Bab 551 / 58

Aturan set operator

  • Jumlah kolom kedua query harus sama, dan data type-nya kompatibel
  • Nama kolom hasil diambil dari query pertama
  • ORDER BY hanya boleh ditulis sekali, di bagian paling akhir

Tips dari lapangan

Gunakan UNION ALL secara default. UNION hanya jika duplikat memang harus dihilangkan, karena prosesnya lebih berat.

Set operator menggabungkan hasil secara vertikal (baris ke bawah); JOIN menggabungkan secara horizontal (kolom ke samping).
